# Execution plan: `cez mcp` — stdio MCP server for supervising cezar tasks

Source doc: .ai/specs/2026-10-06-cez-mcp.md (spec PR sheeerth/cezar#6; Phases 2–4 — Phase 1 ships as sheeerth/cezar#7)

## Goal

A Claude Code session can start, wait for, inspect, message, continue and cancel cezar tasks through `cez mcp` — a stdio MCP server that is a thin client of the running cockpit.

## Scope

- New `packages/cezar/src/mcp/` (`index.ts`, `cockpit.ts`, `projects.ts`, `tools.ts`, `wait.ts`) + tests.
- `packages/cezar/src/index.ts`: `mcp` routed before `parseArgs`, lazy import.
- `packages/cezar/package.json`: `@modelcontextprotocol/server` 2.3.1; `CODE_REVIEW.md:52` budget line.
- `packages/cezar/test/e2e/`: packed-tarball stdio smoke.
- Docs: `docs/reference.md`, `BACKWARD_COMPATIBILITY.md` §1, README install path.

Non-goals (spec): HTTP `/api/v1/mcp`, PR/merge/push/delete/config tools, `afterSeq`, dispatch/report tools, auto-starting the cockpit, any server route change.

## Deviations / decisions recorded during the run

- `start_run` input is picked from the contract `createRunInputBaseSchema` and refined in `tools.ts` (`workflow` defaults to `quick-task`). Phase 1 (#7) is not a prerequisite: the route's local schema is field-identical today.
- A8 gate: the env-forwarding check was run before Phase 3 — Claude Code 2.1.280 forwards its full environment (incl. `CEZ_TASK_ID`) and its cwd to stdio MCP servers (probe: `claude -p --mcp-config` with a logging stdio server). Recorded in the PR.

## Risks

- New runtime dependency (two packages) — loaded only behind the lazy import.
- Web vitest suites fail under local Node 24 independent of this change (jsdom localStorage); CI pins Node 20.
